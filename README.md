# コマ割りカタログ

2〜7コマの漫画ページ構成を、コマ数と性格（動的／静的／大ゴマ含む など）で
絞り込んで比較するブラウザ単体アプリ。

## 使い方

`index.html` をブラウザで開くだけ。ビルド不要・依存パッケージなし。

`file://` でも動きますが、実測データの保存（localStorage）が制限される場合があるため、
簡易サーバー経由を推奨します。

```
python serve.py
# → http://127.0.0.1:8137/
```

配信範囲をこのプロジェクト配下だけに限り、127.0.0.1 のみで待ち受けます。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨格 |
| `style.css` | スタイル（ライト／ダーク自動対応） |
| `geom.js` | 幾何ユーティリティ。段構成・タグ判定の唯一の実装 |
| `data.js` | コマ割りパターンの構造シードデータ（36 パターン） |
| `import.js` | Manga109 アノテーション XML の解析・集計 |
| `editor.js` | コマ割りエディタと自作パターンの保存 |
| `app.js` | 描画・絞り込み・並べ替え・詳細表示 |
| `serve.py` | ローカル確認用の簡易サーバー（アプリ本体には不要） |

読み込み順は `geom.js → data.js → import.js → editor.js → app.js`。
`data.js` は読み込み時に `geom.js` の判定関数でシグネチャとタグを組み立てるため、
この順序を崩すと起動しません。

## データの二層構造

このアプリのランキングは **2 層** に分かれています。両者を混同しないよう、
UI 上でも常にバッジで区別されます。

### 1. 推定スコア（初期状態）

`data.js` の `est`（0–100）。漫画の作画技法で一般に定番とされる構成を踏まえた
**主観的な推定値**であり、実際の作品を数えた統計ではありません。

### 2. 実測頻度（Manga109 取り込み後）

[Manga109](http://www.manga109.org/) は 109 冊分のコマ枠座標が注釈された学術用
データセットです。**入手・利用条件への同意は利用者自身が配布元で行ってください。**
本リポジトリにはデータは含まれません。

入手済みの `annotations/*.xml` をページ下部のフォームから選ぶと、
ブラウザ内だけで解析し、集計結果のみを localStorage に保存します。
XML はどこにも送信されず、画像も一切読み込みません。

## コマ割りエディタ

ページの上でドラッグして分割線を引き、コマを割っていきます。

| 操作 | 結果 |
|---|---|
| コマの上を横にドラッグ | ドラッグの中点を通る**水平**の分割線が入る |
| コマの上を縦にドラッグ | ドラッグの中点を通る**垂直**の分割線が入る |
| Shift を押しながらドラッグ | ドラッグした線そのものの角度で割る（斜め分割） |
| 「重ねゴマ」モードでドラッグ | その範囲に重ねゴマを追加する |
| 「線を動かす」モードで境界線をドラッグ | その線を垂直な向きに平行移動する |
| 「読み順の入れ替え」モードでコマを2つクリック | その2コマの読み順を入れ替える |

「水平・垂直にスナップ」を切ると既定が自由角度になり、Shift の意味が反転します。

### 線を動かす

境界線に近づけると線が光り、ドラッグするとその線が**傾きを保ったまま平行移動**します。

コマは互いに独立したポリゴンとして持っているため、「1本の線」は複数コマの辺の
集まりです。そこで、つかんだ辺と**同じ直線上にあり、かつ区間が繋がっている辺**を
まとめて動かします。

- 「上1コマ＋下3コマ」の横線のように 4 コマに接している線も、1 本として一度に動く
- 2段組で各段に別々の縦線がある場合（区間が繋がっていない）は、別の線として独立に動く
- **ページの外枠はつかめません**

外枠に接している頂点は、法線方向ではなく**枠に沿ってスライド**します。斜めの線を
動かしたときに端点がページの外へ出ないようにするためで、これにより傾きが保たれます。

コマが細くなりすぎる位置（辺がページ座標で 6 未満）や、ページからはみ出す位置には
動かせません。その場合は直前の有効な位置で止まります。

### 反転

「左右反転」「上下反転」でページ全体を反転できます。2回押せば完全に元に戻ります。

右から左に読む前提では、**左右反転したコマ割りは元とは別のコマ割り**です
（大ゴマが右にあるか左にあるかで視線の入り方が変わる）。そのため表示上の設定ではなく、
反転した結果を別パターンとして保存する編集操作にしています。

- **左右反転** … 段構成シグネチャとタグは変わりません（段のコマ数・面積比・斜めかどうかは左右反転で保存されるため）
- **上下反転** … シグネチャは変わります（`1-2` の上大ゴマは反転すると `2-1` の下大ゴマになる）

### 読み順

既定では形状から自動判定します（右上 → 左 → 下段）。ただし斜め分割や重ねゴマでは
意図とずれることがあるため、手で入れ替えられます。

一度でも手で入れ替えると**手動モード**に切り替わり、以後は自動整列しません。
この状態でコマを分割すると、できた2コマは**元のコマがあった位置に差し込まれる**ので、
調整した並びは崩れません。「読み順を自動に戻す」で形状ベースの判定に戻せます。

ただし**反転したときだけは読み順を自動判定に振り直します**。反転すると読み順の前提
そのものが変わる（特に上下反転では先頭と末尾が入れ替わる）ため、手動の並びをそのまま
引き継ぐと必ず破綻するからです。手動調整を残したい場合は「元に戻す」で復帰できます。

カタログの詳細から「この構成をエディタで開く」で読み込んだ場合も、
元のパターンが持つ読み順をそのまま引き継ぎます（自動整列で書き換えません）。

編集のたびに**コマ数・段構成シグネチャ・性格タグ・同じ構成の既存パターン**が
再計算されます。実測データを取り込んでいれば、その構成の実測出現率も出ます。

「カタログに追加」で localStorage に保存され、上のカタログに「自作」バッジ付きで
並びます。分類はすべて形状から自動導出するので、既存パターンとまったく同じ条件で
絞り込み・並べ替えができます。カタログの詳細から「この構成をエディタで開く」で
既存パターンを下敷きにした改変もできます。

対象は 2〜7 コマです。それ以外は保存できません。

## 分類ルール

シードも自作パターンも Manga109 の集計も、すべて `geom.js` の同じ関数で判定します。
手書きのタグは持ちません（同じ形なのに分類が変わるのを避けるため）。

| タグ | 判定 |
|---|---|
| 斜め / 動的 | 軸平行でない辺を持つコマがある |
| 重ねゴマ / 動的 | コマの面積合計がページ面積を 2% 超える |
| 静的 | 上の2つのどちらでもない |
| 大ゴマ含む | 最大コマの面積が、残りのコマの平均の 1.5 倍超 |
| 縦割り | 縦横比 1.6 超のコマが 2 つ以上並ぶ段がある（ページ比 100:142 で計算） |
| グリッド | 全段のコマ数・段の高さ・段内の幅がすべて揃う（2段だけの横割りは除く） |
| 密 | 6 コマ以上 |

**段の定義**: y 方向に半分以上重なり、かつ既にその段にあるコマと x 方向で
半分以上は重ならないコマを、同じ段とみなします。2つ目の条件がないと、
斜め分割や重ねゴマで上下に並んだコマまで「横並びの1段」と誤判定されます。

## 座標系と読み順

- ページを `0..1` に正規化（左上が原点）。ページ比は約 `100 : 142`（B5 系）。
- `cells` 配列の並びがそのまま読み順。日本の漫画に合わせ **右上 → 左 → 下段**。
- 各コマはポリゴン（頂点配列）。矩形も斜め分割も同じ形式で表現します。

## 構造シグネチャ

段構成をコマ数で表した文字列。例:

- `1-2` … 上に 1 コマ、下段に 2 コマ
- `2-2-2` … 3 段それぞれ 2 コマ
- `3` … 1 段を 3 分割（縦割り）

段の判定基準は「分類ルール」の節を参照。

実測データはこのシグネチャ単位で集計されるため、
**同じシグネチャを持つ複数パターンには同じ実測値が表示されます**
（詳細画面に該当パターン名が併記されます）。

## 実測でわかること／わからないこと

Manga109 のコマ枠は軸に平行な外接矩形です。したがって:

| 項目 | 実測可否 |
|---|---|
| コマ数の分布 | ○ |
| 段構成（シグネチャ） | ○ |
| 大ゴマ率 | ○ |
| 斜め分割 | ✕ |
| 重ねゴマ | ✕ |
| 断ち切り（ぶち抜き） | △（枠がページ端に接するかで近似可能。未実装） |

外接矩形しか無いため、**斜め分割と重ねゴマは実測できません**。
「動的／静的」のタグも形状から導く分類であり、実測統計ではありません。

## パターンを追加する

画面上のエディタで作るのが早いですが、シードとして同梱したい場合は
`data.js` の `LAYOUTS` に追記します。シグネチャとタグは自動導出されるので、
形・説明文・推定スコアだけを書きます。

段構成で表せる場合は `T()`:

```js
T('p4-1-2-1', 4, '上大1＋中2＋下1',
  [{ h: 1.5, cols: [1] }, { h: 1, cols: [1, 1] }, { h: 1.1, cols: [1] }],
  '説明文', 97),
```

`cols` は **右から左** の順（読み順と同じ）。`h` と `cols` の値は比率で、
合計が 1 でなくても自動で正規化されます。

斜めや重ねゴマなど不規則な形は `P()` でポリゴンを直接指定します:

```js
P('p2-diag', 2, '斜め2分割',
  [ [[0,0],[1,0],[1,0.66],[0,0.34]],
    [[0,0.34],[1,0.66],[1,1],[0,1]] ],
  '説明文', 46),
```

## 収集についての方針

商用の電子コミックストア・同人配信サイトからの自動収集は行いません
（各サービスの利用規約および著作権のため）。
本アプリが扱うのはコマの幾何構造のみで、作品画像は一切含みません。
